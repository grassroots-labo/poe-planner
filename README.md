# PoE Planner

APの型番と台数から、候補のPoEスイッチ・インジェクタの給電電力と有線リンク速度を確認する小さな実務用ツールです。Chrome Manifest V3 / sidePanel方式。APIキー・ビルド・外部ライブラリは不要です。

**試作 v0.2.0。実機の接続・実効速度・総合的な通信互換を保証するものではありません。**

## すぐ試す

GitHubの **Code → Download ZIP** でソースを取得し、解凍して以下の手順で試せます。

### 拡張をインストールせず画面を試す

`extension/sidepanel.html` をブラウザで開きます。すべて同梱スクリプトで動きます。これは通常ページのプレビューであり、Chrome拡張のsidePanel動作検証ではありません。

Node.js 22以降があれば、プロジェクトフォルダーで次も使えます。依存パッケージのインストールは不要です。

```text
npm run serve
```

表示された `http://127.0.0.1:8765` を開きます。終了は `Ctrl+C`。サーバーはローカルホストにのみ接続を受け付けます。外部ホスティングやデプロイはしません。

### Chrome拡張として試す手順（利用者が任意に実施）

1. 配布ZIPを解凍します。
2. Chrome 116以降で `chrome://extensions` を開きます。
3. デベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」を選びます。
4. `manifest.json` が入っている **`extension` フォルダー**を選びます。
5. 拡張のツールバーボタンを押し、サイドパネルを開きます。
6. 終了後は `chrome://extensions` で削除できます。

利用者の日常のブラウザへのインストールや権限付与は実行していません。検証にはGoogle公式Chrome for Testingと新規の隔離プロファイルを使用しました。Chromeウェブストアの配信物ではありません。

## 使い方

1. APのモデルと台数を選びます。「機器を追加」で異なるAPやカメラ等を混在できます。
2. スイッチを選びます。上流などにPoEポートを使う場合は「利用できないPoEポート数」を入力します。
3. スイッチの割当設定を確認します。初期値「未確認」では電力条件を合格にしません。
4. 他の機器分をPSE割当合計とポート数で入力します。機器行と二重計上しないでください。他機器の規格・1ポート上限を確認してから確認済みにします。
5. 任意の余裕率と希望リンク速度を選びます。変更すると即座に再計算します。

手入力モデルではPD最大消費電力・必要PoE規格・明記された対応速度集合を入力できます。分からない値は空欄にします。PoEクラスやPSE必要量が分かったときは補足欄に入力します。PSE確認値には根拠メモも必要です。

### 三つの電力割当条件

| 条件 | 判定に使う量 | 未確認なら |
| --- | --- | --- |
| 規格上限で予約する設定を確認済み | af=15.4W / at=30W / bt Type3=60W / Type4=90Wを1台ごとに予約 | 規格不明は要確認 |
| PoEクラスで予約する設定を確認済み | 入力したClass 0〜8のPSE給電上限 | クラス不明は要確認 |
| PSE側の必要量・設定値を確認済み | ユーザーが資料や設定で確認した最大必要量と根拠 | 値または根拠が欠ければ要確認 |

規格上限の予約は保守的な設計条件であり、そのスイッチの現在設定を自動判別した値ではありません。LLDP・動的割当・ポート上限設定を使う場合は、起動時・最大負荷とケーブル損失を含むPSE側必要量を別途確認してください。現在の低い実測値だけでは保証できません。確認済みPSE値が予約値を上回る場合は、大きい方を使用します。

### 判定の意味

- **満たす**：入力された条件の比較で必要量以内。
- **不足**：対応規格・1ポート上限・全体予算・ポート数・希望速度のいずれかに不足がある。項目別に理由を表示。
- **要確認**：必要な仕様や設定が不明で、合格を確定できない。

基本の給電判定は、規格・1ポート・総予算・ポート数・他機器をまとめます。**余裕率と希望速度は別判定**です。余裕率を増やしても必要PoE規格は変わりません。

PDは受電側、PSEは給電側です。PDの消費電力×台数をそのままPSE総予算と比較して合格にすることはありません。既知のPD最大値だけで予算を超える場合は、最大負荷の設計条件として不足を示せます。PSE量が分からなければ余裕率を掛けても要確認です。

例：WLX322は仕様上最大16Wでも802.3at必須です。afでは起動しても無線通信ができません。at上限予約を確認した条件で2台なら60Wとなり、GS110TPv3の55Wには5W不足します。これは実消費32Wの見積りとは異なる予約条件です。

### 有線速度

AP側とスイッチの**PoEポート**側に明記された速度集合の共通部分から上限を表示します。10G対応だけで2.5G/5G対応を仮定しません。集合が不明・共通速度が未確認なら要確認です。

WLX322は100M/1G/2.5G。内蔵スイッチのPoEポートは今回資料で確認できた1Gのみ登録しています。この組合せは確認できたリンク上限1Gで、APの2.5G上限を活かせません。希望条件を「1Gでも許容」に変えると速度の評価が変わります。電力判定は変わりません。

上流アップリンクは別に表示します。SFPのトランシーバー・上流機器・集約帯域・ケーブル規格や距離・Ethernet設定は今回未検証です。表示はリンク上限であり、実効速度や通信全体の適合保証ではありません。

## 仕様ページからマスター登録

1. 対象のHTML仕様ページをChromeで開き、そのタブで拡張のツールバーボタンを押します。別タブへ移った場合も対象タブで押し直します。
2. サイドパネル上部でAP・受電機器／PoEスイッチ／PoEインジェクタを選び、「このタブの仕様を取り込む」を押します。
3. 元仕様と照合して候補値を確認・修正します。出典URL・取得日時と項目ごとの抽出根拠を表示します。候補を取得しただけでは保存しません。
4. 「確認してローカル保存」でこのChromeプロファイルに保存します。計算のモデル選択肢から再利用できます。
5. 同じ種類のモデル名または出典URLがある場合は、明示的に既存データを更新するか、別型番として保存するか選びます。キャンセルでは変更しません。「保存済みマスター」から修正・削除もできます。

未知の値・競合する値は空欄です。AP消費電力をPSE必要量へ、スイッチ本体の消費電力をPoE予算へ代入しません。インジェクタは入力電力と出力を分離し、給電方式がパッシブまたは不明ならIEEE互換を確定しません。出力ポートが1つと確認されたインジェクタのみ、1出力のPSE上限を全体上限にも使います。

現状はHTMLの単純な仕様表・テキストを対象とするルール抽出です。日本語・英語のサンプル表で検証しました。全メーカー対応ではなく、複数型番を併記した表、分割された文章、動的ページ、画像、PDFは正しく読めない場合があります。公式カタログ値の検証と、各メーカーのページ形式の自動抽出対応は別です。読めない場合は「手入力で登録」へ進めます。元ページを表示して最終確認してください。価格・在庫・終売の監視はしません。

## プライバシーと権限

権限は `sidePanel`、`activeTab`、`scripting`、`storage`。v0.1から後者3つを追加しています。`activeTab` は対象ページでの拡張アイコンクリック時だけの一時的なアクセス、`scripting` は取込ボタンでメインフレームの表示テキストを読むため、`storage` は確認したマスターをこのChromeプロファイルに保持するためです。通常Chromeへの更新・権限承諾は利用者自身が任意に行います。

host_permissions・常駐content_scripts・全サイト読取・自動巡回はありません。分析タグ、外部JS、APIキー、バックエンド送信、クラウド同期もありません。CSPは `connect-src 'none'`。出典リンクを押すと外部ページへ移動します。AI/APIへの接続機能は現在の配布拡張に含みません。

計算入力は画面のメモリー内、確認保存したマスターだけを `chrome.storage.local` に保持します。再起動後もマスターを再利用できます。通常HTMLプレビューでは同じブラウザのlocalStorageを使います。拡張の削除やブラウザデータ消去で失われる場合があります。現時点でエクスポート・同期機能はありません。

## 開発・検証

Node.js 22以降（検証時 v24.22.1）。Python 3標準ライブラリはZIP作成時のみ必要です。

```text
npm test
npm run serve
npm run package
```

UI自動テストはサーバー起動後、`http://127.0.0.1:8765/tests/browser.html` をChromeで開きます。`ALL_PASS` と件数を確認してください。これも通常ページのUIテストです。

v0.2の検証結果と未実施項目は [TESTING.md](TESTING.md) を参照してください。通常ページのテストと、隔離Chrome for Testingでの実sidePanel・一時権限・保存・再起動テストを区別して記録しています。

## ファイル

- `extension/`：そのまま読み込める拡張。HTML/CSS/JavaScriptのみ。
- `tests/`：電力・速度・不正入力・権限のテスト、ブラウザUIテスト。
- `scripts/`：ローカルプレビュー、許可リスト方式のZIP作成。
- `dist/`：ローカル生成ZIPとSHA-256。Gitの対象外。
- `evidence/`：ローカル検証用の画面やログ。一切公開対象にしません。
